# Snowflake JSON CDC Pipeline

## Overview

Practiced loading semi-structured JSON data from Amazon S3 into Snowflake using an external stage and a `VARIANT` column.

Implemented Snowflake Streams and Tasks to automatically process new JSON records and `MERGE` them into a structured `LINEITEM` target table.

## Pipeline Flow

```text
Amazon S3
   ↓
External Stage
   ↓ COPY INTO
LINEITEM_RAW_JSON1
   (SRC VARIANT)
   ↓
LINEITEM_STD_STREAM
   ↓
Task
   ↓ MERGE
LINEITEM
   (Structured Target)
```

## 1. External Stage

Created an external stage connected to the S3 location using a Snowflake Storage Integration.

The stage points to the location where the JSON files are stored.

```sql
CREATE OR REPLACE STAGE stg_lineitem_json_dev
STORAGE_INTEGRATION = aws_sf_data
URL = 's3://<YOUR_S3_BUCKET>/<YOUR_PATH>/'
FILE_FORMAT = json_load_format;
```

Checked files available in the stage:

```sql
LIST @stg_lineitem_json_dev;
```

## 2. JSON File Format

Created a JSON file format:

```sql
CREATE OR REPLACE FILE FORMAT json_load_format
TYPE = 'JSON';
```

## 3. Raw JSON / VARIANT Table

Created a raw table with a `VARIANT` column.

```sql
CREATE OR REPLACE TABLE lineitem_raw_json1 (
    src VARIANT
);
```

The complete JSON object is stored inside the `SRC` column.

## 4. Load JSON from S3 into VARIANT

Used `COPY INTO` to load the JSON file from the external stage into the raw table.

```sql
COPY INTO lineitem_raw_json1
FROM @stg_lineitem_json_dev
ON_ERROR = ABORT_STATEMENT;
```

The stage is the file location, while `LINEITEM_RAW_JSON1` is the Snowflake table that stores the loaded JSON data.

A new JSON file with a different filename can be loaded into the same `LINEITEM_RAW_JSON1` table.

## 5. View VARIANT Data

Viewed the complete JSON object:

```sql
SELECT *
FROM lineitem_raw_json1;
```

or:

```sql
SELECT SRC
FROM lineitem_raw_json1;
```

Extracted individual JSON attributes:

```sql
SELECT
    SRC:L_ORDERKEY AS L_ORDERKEY,
    SRC:L_PARTKEY AS L_PARTKEY,
    SRC:L_QUANTITY AS L_QUANTITY,
    SRC:L_EXTENDEDPRICE AS L_EXTENDEDPRICE,
    SRC:L_SHIPMODE AS L_SHIPMODE
FROM lineitem_raw_json1;
```

JSON values can also be explicitly converted to required data types:

```sql
SELECT
    SRC:L_ORDERKEY::INT AS L_ORDERKEY,
    SRC:L_QUANTITY::FLOAT AS L_QUANTITY,
    SRC:L_EXTENDEDPRICE::FLOAT AS L_EXTENDEDPRICE,
    SRC:L_COMMENT::STRING AS L_COMMENT
FROM lineitem_raw_json1;
```

## 6. Stream for CDC

Created a standard Stream on the raw JSON table:

```sql
CREATE OR REPLACE STREAM lineitem_std_stream
ON TABLE lineitem_raw_json1;
```

The Stream tracks changes made to `LINEITEM_RAW_JSON1`.

## 7. Task for Automated Processing

Created a Task that runs on a schedule and checks whether the Stream contains new data.

```sql
CREATE OR REPLACE TASK lineitem_load_tsk1
WAREHOUSE = compute_wh
SCHEDULE = '1 minute'
WHEN SYSTEM$STREAM_HAS_DATA('lineitem_std_stream')
AS
MERGE INTO lineitem AS li
...
```

`SYSTEM$STREAM_HAS_DATA()` prevents the Task from processing when there are no new Stream records.

## 8. Extract JSON Fields

Used JSON path expressions to extract fields from the `VARIANT` column:

```sql
SRC:L_ORDERKEY
SRC:L_PARTKEY
SRC:L_QUANTITY
SRC:L_EXTENDEDPRICE
SRC:L_SHIPDATE
SRC:L_SHIPMODE
```

These values were used as the source dataset for the `MERGE`.

## 9. MERGE into Structured Target

Used `MERGE` to incrementally load the structured `LINEITEM` table.

```text
Stream
   ↓
Extract JSON fields
   ↓
MERGE
   ├── Matched → UPDATE
   └── Not matched → INSERT
```

The existing `LINEITEM` table already contains its own column definitions and data types.

The raw table does not need to define every `LINEITEM` datatype because it stores the JSON as `VARIANT`.

## 10. New JSON File Practice

After completing the first load and `MERGE`, created another JSON file with different data.

The new file can still be loaded into the same raw table:

```sql
COPY INTO lineitem_raw_json1
FROM @stg_lineitem_json_dev
ON_ERROR = ABORT_STATEMENT;
```

Then the newly loaded records can be viewed with:

```sql
SELECT *
FROM lineitem_raw_json1;
```

The new rows are detected by the Stream and can subsequently be processed by the Task and `MERGE`.

## Final Architecture

```text
                Amazon S3
                   │
                   │ JSON files
                   ↓
          External Snowflake Stage
                   │
                   │ COPY INTO
                   ↓
          LINEITEM_RAW_JSON1
             SRC = VARIANT
                   │
                   ↓
        LINEITEM_STD_STREAM
                   │
                   ↓
          Scheduled Task
          (checks for data)
                   │
                   ↓
              MERGE
                   │
          ┌────────┴────────┐
          ↓                 ↓
       UPDATE             INSERT
          └────────┬────────┘
                   ↓
               LINEITEM
          Structured Target
```
